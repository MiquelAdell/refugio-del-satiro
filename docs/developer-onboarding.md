# Developer onboarding — Refugio del Sátiro

Orientation for developers new to this codebase. It gives you the big
picture and points to the documents that hold the details — it does not
repeat them. Repo: `refugio-del-satiro`; ongoing work happens on the
`development` branch.

## What this is

The public site of a board game club, https://www.refugiodelsatiro.es,
made of two halves served from the same origin:

1. **Content mirror** (everything except `/ludoteca`) — the club's
   Google Sites pages, scraped into static HTML and served by Caddy.
   Editors keep editing in Google Sites; a scraper refreshes the mirror
   (nightly cron, plus an on-demand "resync" button in the admin UI).
2. **Ludoteca** (`/ludoteca/*`) — a game lending app: a React SPA backed
   by a FastAPI API. Members browse the catalog, borrow and return games;
   admins manage members and trigger content resyncs.

## Stack at a glance

- **Backend**: Python 3.12+, FastAPI, SQLite (single file), clean
  architecture (domain / data / api layers).
- **Frontend**: React + TypeScript + Vite, React Router
  (`basename="/ludoteca"`). Spanish UI, no i18n runtime.
- **CLI**: Typer, installed as `refugio` (migrations, imports, scraper).
- **Infra**: Caddy reverse proxy (auto-HTTPS), Docker Compose on a VPS,
  GitHub Actions auto-deploy on push to `development`. An alternative
  Render deployment exists (`render.yaml`).
- **Tests**: pytest (backend + scraper), Vitest (frontend), Playwright
  (`e2e/`).

## Key concepts in five minutes

**Database** — four tables: `games` (holds both board games and RPG items,
discriminated by `item_type`), `members`, `loans`, `password_tokens`.
A partial unique index on `loans` enforces one active loan per game
(`WHERE returned_at IS NULL`). Migrations run automatically on first DB
access and via `refugio migrate`.

**Auth** — bcrypt passwords, JWT (HS256, 7-day expiry) in an httpOnly
cookie named `session_token`. There is no separate admin login: admin is
just the `members.is_admin` flag, granted via CSV import (`admin=yes`)
or the CLI, and enforced server-side (403) and client-side. New members
never receive a password: they get a one-time, 48-hour set-password link
generated by an admin.

**Content mirror lifecycle** — the scraper (run nightly, or from the
admin "Contenido" page, or locally with `refugio content run`) rewrites
the mirror that Caddy serves. The admin resync updates the **live VPS
cache only**; to persist changes, run the scraper locally and commit the
diff under `frontend/public/content-mirror/`.

**Catalog data** — there is no admin UI for games. The catalog is seeded
from BoardGameGeek via `refugio import-games` / `refugio import-rol`.

**Planning workflow** — changes are planned in `openspec/` (proposal →
design → tasks; accepted specs live in `openspec/specs/`). Check
`openspec/changes/` for in-flight work before touching a feature — e.g.
`lending-borrow-with-return-date` will change the borrow flow.

## Getting it running

```bash
pip install -e ".[dev]"        # backend + the `refugio` CLI
cd frontend && npm install && cd ..
refugio migrate
refugio import-games data/bgg_collection.json
refugio import-rol
refugio import-members members.csv --base-url http://localhost:5173/ludoteca
./dev.sh                       # backend + mirror + Vite + Caddy
```

Open **http://localhost:2015**. `dev.sh` starts four processes (uvicorn
:8000, static mirror :8080, Vite :5173, Caddy :2015) and kills them
together on Ctrl-C. The README documents two lighter setups (lending app
only; scraped site only) and the production-like Docker one.

## Gotchas

- **Docker bakes the frontend at build time** — after frontend changes,
  `docker compose up --build`; a restart is not enough.
- **Admin resync ≠ committed** — see the content mirror lifecycle above.
- **`REFUGIO_JWT_SECRET` must be set in production**; the default is a
  dev-only secret. Full env var table in the README.
- **Member editing in the UI is deliberately narrow** (last payment +
  gender); everything else flows through CSV re-import, which upserts
  by email.
