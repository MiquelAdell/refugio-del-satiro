# Issue #104 — Member profile information page

Status: **complete** — GitHub issue closed.

## Context

[GitHub issue #104](https://github.com/MiquelAdell/refugio-del-satiro/issues/104) requires an authenticated, read-only profile where a member can see their membership number, name, nickname, email, phone, active/payment status, and links to their loans and password-change flows. The existing authenticated `GET /api/me` response is the natural contract to extend: it already resolves the member exclusively from the signed session cookie through `CurrentMember`, but serializes only `id`, `display_name`, `email`, and `is_admin` (`backend/api/routes/auth_routes.py:48-65`, `backend/api/routes/auth_routes.py:91-93`). The underlying frozen entity already contains all requested source-controlled fields plus sensitive/internal fields that must remain excluded (`backend/domain/entities/member.py:7-23`), and authentication returns 401 when the cookie cannot resolve a member (`backend/api/dependencies.py:147-170`).

The React auth provider already fetches `/me` on session restoration and after login (`frontend/src/context/AuthContext.tsx:16-41`), so the profile page should render that authoritative `CurrentMember` rather than issue a duplicate request. There is currently no `/profile` route (`frontend/src/App.tsx:20-132`), and the user submenu links only to loans, password change, administration, and logout (`frontend/src/components/SiteHeader/SiteHeader.tsx:83-137`). Add the profile entry to that submenu and keep the page read-only: member data is sourced from imports/admin workflows, and issue #104 explicitly excludes self-editing.

Use one agreed `/api/me` JSON contract across backend and frontend: `id`, `member_number`, `first_name`, `last_name`, `nickname`, `phone`, `email`, `display_name`, `is_admin`, `is_active`, and `last_payment`. Nullable source fields remain nullable. Do not expose `password_hash`, `created_at`, `updated_at`, or `gender`; `is_admin` remains in the response because the existing client uses it for authorization-aware navigation (`frontend/src/components/SiteHeader/SiteHeader.tsx:142-157`). User-facing copy stays Spanish, matching the repository convention (`README.md:21-26`).
